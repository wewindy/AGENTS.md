若我没有明确某条要求，遵守下属规定。

- 风格上
  - 常量使用大写词汇、下划线拼接
  - 变量、成员用小写字母开头的驼峰命名，私有变量可以适当使用下划线开头
  - 类、枚举、接口、类型使用 PascalCase 命名
  - 使用简单英文词汇命名，避免动词开头
- 承担能力契约、依赖注入协议或可实现约定的 `interface` 使用 `I` 前缀
- 普通数据结构的 `interface` 和 `type` 使用 PascalCase，不用 `I` 前缀
- 若非必要，禁止使用 `any`、`as any`、`as unknown as T`
- 避免行首使用分号 + `(XX as Type).xx` 的书写风格，若要断言优先使用新变量
- 数组要用 `T[]` 而不是 `Array<T>`
- 代码组织上
  - 导入的依赖要按字母顺序排列
  - 目录名优先使用 kebab-case
  - 模块目录应提供 `index.ts` 出口，集中对外导出成员
  - 类单独放在同名文件中
  - 类型、接口尽可能抽离独立文件到最近的 `types` 目录
- 写注释
  - 注释要简单明了，不要长篇大论
  - 关键逻辑、变量写 note 类型的多行注释
  - 注释说明“为什么”、“来源”等关键信息，不逐行翻译代码
  - 类、函数、字段、类型等需要暴露给别人用的地方，均使用 `TSDoc`
